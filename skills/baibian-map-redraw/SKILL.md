# 百变剧本地图重绘

用于旧剧本地图的重新绘制，不用于普通图片生成或仅放大现有地图。

## 先分析，再生成

1. 从 Excel 的剧本 ID、名称和后台链接读取主要剧情；核对地图列表、地点管理和地图热区。
2. 分析原图的空间结构、主题、已有搜证地点与按钮。保留所有已有搜证地点的名称和数量；位置可为新版构图调整。
3. 同一剧本有多张地图时，先确定共用的画风、透视、光影、色彩、材质、字体与按钮语言，再逐张绘制。
4. 按剧本题材选择美术方向：欢乐本偏明快卡通；重度推理偏克制的半写实；情感恋爱本偏唯美柔和。人物只在能加强场景氛围时作为小比例环境元素出现。
5. 先判断场景时间：优先延续原地图的白天/夜晚设定；再用剧本明确时间线校验。若时间线与原图冲突，以剧本事件实际发生时段为准。没有明确依据时不得仅为“悬疑感”擅自将日景改成夜景。
6. 地图将被游戏四周 UI 遮挡：生成时必须把镜头后退约 **1.2 倍**，所有可交互的主体建筑、房间、道路和关键物件均收纳在正方形画布中央约 **70%×70%** 的安全区域内。外围每边约 15% 只用于可延展、非关键信息的氛围环境（如树木、山石、水面、远景建筑、天空、街景）；关键地点不得贴边或依赖边缘细节识别。此要求应写入每一次地图提示词，而不能仅在导出时缩放或裁切。
7. 绘制室内多房间地图时，须在提示词中明确选择一种**一致的建筑表达**：要么是自洽的整层“前向剖面 / dollhouse cutaway”，要么是完整外观的建筑鸟瞰，二者不得混用。尤其禁止把切开的单层房间放在完整高层建筑顶部，同时又显示下方多层立面；这种组合会造成“人在楼顶”的错误观感。若采用剖面图，指定“不是屋顶、不是露天楼顶、不可见下方楼层”，外围安全区应延续为走廊、楼梯间、邻楼墙体、树影或夜色，而非拼接写实城市鸟瞰背景。

## 分辨率与输出

- 当前批准的主流程是调用 ZenMux 的 OpenAI 兼容图片接口，使用 `openai/gpt-image-2.5-sunburst` 生成 **2K、1:1 正方形**源图，再在本地高质量调整为 **2880×2880**。
- 这里的 2K 要求只针对最终地图底图；地图底图不得使用 Codex 内置图像生成工具的小尺寸结果作为正式源图。
- 2K 源图转 2880×2880 的交付物必须标注为“ZenMux 2K 生成后本地转换”，不得表述为原生 2880×2880。
- 如果后续受控 API 能稳定、明确地原生输出 2880×2880，则原生 2880 优先；否则按上述 ZenMux 2K 流程执行，不再降级到未知尺寸或内置工具生成的小图。
- ZenMux API 地址为 `https://zenmux.ai/api/v1/images/generations`；密钥只从本机环境变量 `ZENMUX_API_KEY` 读取，禁止写入项目文件、脚本、日志或聊天记录。
- 成品统一为 JPEG，2880×2880，单张目标约 2 MB；通过生成后 JPEG 压缩控制体积。
- 原图必须保留；重绘文件保存到对应的 `ID+剧本名称` 文件夹。

## ZenMux 配置与调用检查

- 使用 ZenMux 图片 API 前，先确认本机已配置环境变量 `ZENMUX_API_KEY`。密钥不得写入项目文件、脚本、日志或聊天记录；如果密钥曾经泄露，必须先在 ZenMux 后台撤销并重新生成。
- `~/.zshrc` 只会被交互式 shell 自动读取，Codex 新会话和桌面应用进程通常不会自动加载它。因此，**不能仅因当前进程未见环境变量就直接中止**。
- 每次 API 连通性检查或生成请求前，先执行以下非输出式加载逻辑，再检查变量是否存在：

  ```bash
  if [ -z "${ZENMUX_API_KEY:-}" ] && [ -f "$HOME/.zshrc" ]; then
    source "$HOME/.zshrc"
  fi
  ```

- 若加载后仍缺失，才提示用户配置；不得输出、回显或记录密钥值。
- 推荐在用户自己的 shell 配置中保存密钥：

  ```bash
  export ZENMUX_API_KEY="新的ZenMux API Key"
  ```

- 为使以后新开的 Codex 桌面会话也能直接继承变量，用户可在本机终端额外执行 `launchctl setenv ZENMUX_API_KEY "新的ZenMux API Key"`，然后完全退出并重新打开 Codex。该命令只由用户在本机手动执行，Skill 和项目内不得包含真实密钥。

- API 基地址为 `https://zenmux.ai/api/v1`，图片生成接口为 `POST https://zenmux.ai/api/v1/images/generations`。
- 开始批量生成前，先使用带鉴权的 `GET https://zenmux.ai/api/v1/models` 做无消耗连通性检查；只输出 HTTP 状态和模型是否存在，不输出响应中的密钥或敏感信息。
- 必须确认模型列表包含 `gpt-image-2.5-sunburst`，再使用模型 ID `openai/gpt-image-2.5-sunburst` 生成地图。
- 生成参数优先使用：正方形 1:1、2K、high 或 auto 质量、JPEG 输出。若接口字段与网页字段不同，以 ZenMux 当前 API 文档为准。
- 生成后立即检查源图尺寸、格式和文件大小，再本地调整为 2880×2880 JPEG；交付记录中注明“ZenMux 2K 生成后本地转换”。
- 不要因为 Codex 文本模型已经切换到 ZenMux 就认为图片接口自动可用；地图生成必须单独调用图片模型。

## 辅助素材的分辨率策略

### 先用内置模型校样“地图 + 按钮”

每张新地图在制作最终交付物前，必须先用 Codex 内置图片生成模型制作一张低成本的**地图/场景 + 已摆放无文字搜证按钮**视觉校样。校样的目的，是在同一张图中验证按钮是否真正继承了该地图的画风、材质、色彩和氛围；它不是正式底图、不是最终透明按钮，也不能替代任一正式交付文件。

- 校样提示词只发送从剧本中提炼出的绘画摘要：时代与地点、叙事气质、时间、场景结构、地点数量与大致落位、风格要求和避雷项。不得将完整剧本、角色故事、线索或复盘原文发送给图片模型。
- 校样图必须让地图与按钮在同一视觉语言中生成；按钮可为无文字占位样式，地点文字仍由 PSD 的可编辑文字层完成。主场景仍须位于画布中央约 70% 的安全区域，四周仅保留氛围延展。
- **校样阶段不得预制按钮美术方案。** 提示词只能约束按钮的功能性条件：无文字、横向主体、地点数量与大致落位、中央可编辑文字安全区、不能遮挡关键场景，以及避免大型挂件/复杂纹样。不得在校样提示词中预先指定颜色、材质、边框、铆钉、图标、纹样或光效；这些视觉决定必须交由模型依据它正在生成的地图自然推导。
- 必须人工查看校样，再提炼该图实际适配的按钮特征：主体轮廓和比例、主辅色、边框线宽、材质与光泽、装饰纹样密度、阴影/发光强度、图标语言、可读文字色。不得仅按剧本题材或通用类型独立猜测按钮风格。
- 从通过校样中截取一个完整、清晰的按钮局部图作为视觉参考；将该参考用于 Codex 内置图像生成的最终按钮提示或编辑输入。若当前生成能力不支持参考输入，必须以裁图提炼出的具体视觉特征补足最终提示词，不能退回为泛用题材按钮。
- Codex 最终无文字按钮生成并完成透明底处理后，须合成到最终底图中复核。只有其材质、配色、装饰复杂度、透视和亮度均与地图匹配，且通过真实 alpha 与可见主体比例检查，才可写入 PSD 和交付。

- 搜证按钮样式探索、无文字按钮草图、构图草图、风格参考和其他非最终地图素材，可以使用 Codex 内置图像生成能力，不要求原生 2K。
- 所有正式交付的无文字搜证按钮必须由 **Codex 内置图像生成模式**生成；不得调用 ZenMux 的图片编辑接口生成透明按钮，也不得用 SVG、Canvas、CSS 或其他代码图形直接绘制按钮主体。代码仅可用于背景清理、透明通道检查、组合预览与 PSD 的精确地点文字。
- **默认按钮生成流程**：先用 Codex 内置图像生成模式制作无文字按钮，要求正面平视、横向主体、中央连续低纹理文字安全区、主体居中并在四周留白。源图使用纯白或单一、明确的纯色背景；不得要求棋盘格背景，也不得依赖模型直接输出透明通道。提示词须明确无文字、无数字、无 Logo、无图标、无场景、无外部光晕/阴影。边框、材质和少量微型铆钉/细线服务于从校样提炼的视觉语言，禁止大型侧翼、具象道具、挂件和复杂纹样。
- **透明底处理（默认交付）**：保留 Codex 原始生成图；从画布四边开始，仅将与边缘连通的白色或约定纯色背景区域设为透明。不得按“绿色/白色等某种颜色一律透明”的色键规则处理，以免误删按钮主体中的浅色纸面、银色高光、绿色边框或同色装饰。若背景与主体接近、或出现邻格污染，先用裁切范围、连通块或手工规则隔离按钮主体，再清理背景。导出 `按钮样式-无文字.png` 为 RGBA PNG；白底检查图可另存，但不得覆盖原始生成图或透明成品。
- **透明底验收**：读取 PNG 元数据并确认四通道/`hasAlpha=true`，透明度范围必须包含 0 与 255；以 alpha 大于 8 的非透明像素包围盒记录按钮主体尺寸与比例。比例不作为强制退回或重新生图条件：风格还原、与地图的适配度、轮廓完整性和真实透明通道优先于宽高比。不得为了命中比例而删掉校样中已经确认的侧翼、端部或其他核心造型，也不得非等比压缩按钮。最后在深、浅两种实色底上合成预览，确认按钮外不残留白底、棋盘格、景物、色晕或白边，主体边缘、挂件、细线和投影完整。
- 辅助素材如果最终进入正式交付，也必须经过尺寸、清晰度、透明背景和文件格式检查；但不应因此替代 ZenMux 生成的 2K 地图底图。
- 地图底图、地图合成预览和最终地图文件遵循上一节的 ZenMux 2K → 本地 2880×2880 流程。
- 原图必须保留；重绘文件保存到对应的 `ID+剧本名称` 文件夹。
- 每张重绘地图默认交付四份新文件：`地图名称-重绘-无按钮.jpg`、`地图名称-重绘-按钮组合预览.jpg`、`按钮样式-无文字.png`，以及 `地图名称-重绘-可编辑.psd`。不输出按地点拆分的带文字按钮文件，除非用户另行要求。用户明确表示不需要 PSD 时，才可省略第四份。

## 默认交付可编辑 PSD

项目当前已确认 PSD 为默认交付。可直接生成分层 PSD；不必启动 Photoshop，除非用户要求以 Photoshop 打开验证。

- 底图命名为 `地图底图（无按钮）`，必须位于所有地点组的最底部。
- 每个搜证地点建立一个以地点名命名的图层组（文件夹）。地点数量与名称须和地图预览、后台地点一致。
- 每个地点组固定包含两层：上方为以地点名命名的可编辑文字层，下方为独立的 `按钮样式-无文字.png` 图层。文字和按钮不得烘焙到同一图层。
- 文字内容使用地点名；按钮初始位置与按钮组合预览对应，但用户可以在 PSD 中整体移动图层组或单独调整文字、按钮。
- 生成后至少校验 PSD 画布尺寸、地点组数量、组名、文字层标记，以及文字层在按钮层上、底图在所有地点组下方。
- 使用 `ag-psd` 写入时，数组写入顺序与 Photoshop 图层面板显示顺序相反：根层应按“底图、地点组的反序”写入，地点组内应按“按钮、文字”写入，才能在 Photoshop 中显示为地点组在上、底图在最下，以及文字在按钮上方。不得仅依赖同库 `readPsd` 的数组顺序作校验；必须按 Photoshop 的实际显示方向反向核验，或在用户要求时以 Photoshop 打开复核。
- `ag-psd` 的 `imageData` 必须传入**解码后的 RGBA 原始像素缓冲区**；绝不可把 `sharp(...).png().toBuffer()` 得到的压缩 PNG 文件字节直接写给 `imageData`，否则 Photoshop 会将其误解释为彩色噪点蒙层。PNG 缓冲区仅可用于组合预览；写入 PSD 前必须经 `ensureAlpha().raw().toBuffer()` 解码。

## 美术与交付检查

- 避免实景照片感、拼贴感、低清、风格混杂、难辨识的按钮及与背景冲突的配色。
- 可以出现必要的环境文字；不依赖模型生成复杂或关键的中文按钮文字。需要精确文字时，在生成后的可控排版阶段添加。
- 组合预览中的按钮须贴近原图的按钮语言和比例；单独的无文字按钮应简洁复刻预览样式，不得为了独立素材而添加原图没有的花纹、配色或厚重边框。
- 除非用户另行指定，按钮生成仍可用 **2:1** 作为构图起点，但不强制最终可见主体符合固定比例。校样中确认的侧翼、端部和装饰轮廓应完整保留；最终比例仅按 alpha > 8 的主体包围盒记录。组合预览须从透明画布的 alpha 主体取图后等比放置，不能把画布留白一起缩放；用户可在 PSD 中自行做比例调整。
- 交付前检查：像素尺寸、JPEG 格式、文件大小、剧本内多图的一致性，以及地点/按钮是否完整保留。
