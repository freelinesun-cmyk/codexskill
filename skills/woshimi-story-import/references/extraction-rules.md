# 文档识别与内容边界

## 预处理

- 优先直接解析 DOCX。旧 `.doc` 可用 Word/WPS/LibreOffice 转为工作 DOCX；不要覆盖源文件。
- DOCX ZIP 的图片 CRC 损坏时，只修复工作副本并记录被替换或恢复的媒体。
- 段内手动换行导致多个逻辑段落粘连时，可在工作副本中拆分为段落，同时复制原 run 样式。
- 表格、文本框、页眉页脚可能不在普通段落流中；扫描结果异常时单独检查这些容器。

## 角色与故事

- 优先从人物介绍和人物剧情角色标题交叉取得角色名；冲突时以人物故事部分的角色标题为准，并在校对文档标注。
- 常见角色标题为 `【角色名】`、`角色名` 或带序号的角色名。不要把“公共投票”“答案”“线索”等章节名当作角色。
- 故事从角色标题之后开始，到下一个角色标题、下一幕或投票/答案/线索等同级章节之前结束。
- 分幕标题保留完整副标题，例如“第一幕 背景故事”“第二幕 时间线”。无幕次时使用源章节标题“人物剧情”。
- 人物剧情区域内若出现“小剧场（公共剧情）”“公共剧情”“公共小剧场”等明确公共剧情标题，将该标题下正文提取为一条独立故事记录，`role` 为 `null`，`roles` 为全部具体角色。标题使用源标题的主体名称（例如“小剧场”）；内容到下一同级章节（如线索搜证、投票、答案）前结束。没有公共剧情时不生成。
- 公共剧情属于人物故事，不得误归入公共投票、圆桌或阶段复盘；后台导入时只创建一条并勾选全部具体角色，不勾“公共角色”。
- 保留段落边界、换行、标点、全半角字符和源富文本；不润色、不合并、不自动改写。

## 投票与圆桌

- 候选标题包含“投票”“圆桌”“讨论”“圆桌阶段”，但正文中的普通用词不算章节标题。
- 标题输出优先级：用户明确指定名称 > 源章节标题 > 明确幕次加“圆桌”的安全回退。不要默认写“单幕剧本圆桌”。
- 角色段以角色名起始；“公共投票/公共圆桌/公共讨论”之后为公共内容。
- 纯角色投票：有内容的每个角色各一条。
- 纯公共投票：只生成一条，`role` 为 `null`，`roles` 为全部具体角色。
- 混排：每个角色生成一条，拼接顺序为公共说明、该角色内容、公共投票内容。
- 删除独立的“正确答案：……”行。括号内容只有在明确属于答案批注时才删；“多选”“以肉身为准”等题意限定应保留。判断不清时在校对文档标注，不擅自删除。
- 输出富文本统一为宋体 12pt、黑色 `#000000`；清除源文档中用于答案标记的红色、黄色高亮、粗体和下划线。

## 阶段复盘

- 可识别“第一幕答案”“第一幕答案解析”“第一幕真相解析”“阶段答案”等与某一幕对应的独立内容。
- 若标题未写幕次，使用它前面最近的明确幕次；无法确定归属时要求人工确认。
- 每幕只生成一条，选择全部具体角色。保留正文的源富文本，处理方式与人物故事一致。
- 位于最后一幕之后、标题为“真相”“最终真相”“真相解析”“最终解析”“全剧真相”“案件复盘”“复盘”“结局”的终局内容默认排除。
- 没有阶段复盘是正常情况，不创建空目录或空 JSON。

## 图片

- 不把图片嵌入任何导入正文。
- 按文档顺序导出到 `文档图片/`，文件名使用 `剧本名-文档图片-001.ext`。
- 记录图片所在段落、幕次、角色或章节，写入生成说明；无法定位时标记“文档其他位置”。
