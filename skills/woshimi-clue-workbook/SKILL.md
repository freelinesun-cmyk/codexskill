# 《我是谜》剧本线索整理

将 DOCX 或原始 XLSX 中的线索搜证内容整理为后台导入表格。默认不处理角色故事、圆桌投票、问题答案和真相解析。

## 必须先确认

执行导出前确认三个数值：调查点起始 ID、线索技能-1 ID、线索技能-2 ID。缺少任一参数时先询问，不猜测、不沿用历史值。

## DOCX 提取规则

1. 识别“一幕搜证”“第一幕线索搜证”“二幕搜证”等线索章节。
2. 每幕只提取从线索正文开始到对应圆桌标题之前的内容；圆桌可能叫“第一轮圆桌”“一幕圆桌”“最终圆桌”或“二幕圆桌”。
3. 线索包通常由 `【人物调查】`、`【场地调查】`、`【尸体检查】`、`【地图】` 等标题标识；标题后的每条编号段落或连续正文是一条线索。
4. 文档在搜证章节前可能重复角色故事标题，不能将这些角色段落当作线索。
5. 保留线索正文和原有标点，只清除开头的数字序号；不要把投票问题、选项、答案、推理解析混入线索。
6. `【地图】` 若明确属于搜证总数，作为一个线索包和一条线索保留。

## 输出格式

生成 Sheet1 六列：

| 线索包名字 | 线索名 | 描述 | 调查点id | 线索技能-1 | 线索技能-2 |
|---|---|---|---:|---:|---:|

- 每个线索包只在第一条填写 `场景一、包名`、`场景二、包名` 等，其余行留空。
- 线索名默认是 `包名1`、`包名2`；只有一条时仍保留编号形式，除非用户指定其他命名。
- 同一线索包的所有行共用一个调查点 ID；按线索包出现顺序从起始 ID 连续递增。
- 每条线索写入用户提供的两个技能 ID，并保存为数值。
- Sheet2 按出现顺序写入纯线索包名称。
- 匹配模板的六列顺序、表头样式、包首行加粗、描述列换行、整数列格式和冻结首行。

## 质量检查

导出前后都检查：线索包数、线索总数、每包边界、调查点 ID 是否严格连续、技能 ID 是否一致、描述是否缺失。导出后重新导入并校验实际落盘值；扫描公式错误并渲染 Sheet1/Sheet2 做可读性检查。始终另存新文件，不覆盖源文件。

## 交付报告

报告输出文件、线索包数量、线索总数、调查点 ID 范围以及文档标题统计与实际识别数量不一致的情况。
