# 制作与验收流程

## 1. 提取线索

完整读取 [标准线索表与卡片映射](clue-workbook-source.md)，先把 DOC/DOCX 整理为标准六列线索 Excel，再从落盘后重新读取的表格生成卡片清单。PSD 标题、正文、顺序和数量只能来自这份通过校验的表格，不再直接从剧本文档临时解析。

识别结构：

- `第一轮搜证`、`第二幕搜证`：轮次或幕次。
- `场景一：思琪`、`场景二：103活动室`：线索卡标题，输出时只保留冒号后的名称。
- 场景后的项目符号或编号段落：每段一条线索，清除开头的 `•`、`1.`、`1、` 等序号。
- 文档标注“共 N 条线索”时，必须与实际识别数逐轮比对。
- `地图` 明确计入搜证总数时，作为一条线索保留。

从标准表建立至少包含以下字段的卡片清单：

```json
{
  "order": 1,
  "round": "第一轮",
  "title": "思琪",
  "sceneIndex": 1,
  "text": "头上戴着降噪耳机"
}
```

## 2. 解析 PSD 模板

优先使用 Node.js `ag-psd` 读取模板，不操作 Photoshop UI。检查：

- 画布尺寸、色彩模式和位深。
- 顶层模板组及其背景、边框、正文、标题图层。
- `text.orientation === "horizontal"` 为正文，`vertical` 为标题。
- 模板字体的 PostScript 名称、字号、颜色、变换矩阵和文本框尺寸。

模板不符合上述命名时按图层类型与方向判断，不依赖固定中文图层名。

## 3. 制作文字版多线索 PSD

为每条线索重新读取或深拷贝模板组，避免共享对象导致跨组改字。每组：

- 名称：`01_第一轮_思琪_1`。
- 替换竖排标题和横排正文，同时更新文字图层名称。
- 为组和所有子图层分配唯一 `layer.id`。
- 长正文使用文本框自动换行，调整字号但不改变横排方向。

`ag-psd` 的 `children` 顺序为底到顶。若要 Photoshop 图层面板自上而下显示 `01` 到 `N`，写入顶层组时需反转数组。只让 `01` 组默认可见。

写出时使用：

```js
writePsdBuffer(psd, {
  noBackground: true,
  invalidateTextLayers: true,
});
```

保留模板字体名。`invalidateTextLayers` 会移除旧文字缓存标记，使 Photoshop 打开后一次性更新全部文字层；不要让用户逐条进入编辑状态刷新。

## 4. 规划和生成配图

先将每条线索映射为明确画面，再调用 `imagegen`；不同线索必须分别生成，不能生成拼图后裁切。

统一提示词要求：

- 用途：剧本杀线索卡配图。
- 横版 16:9，精致二维卡通/动漫插画，清晰线条和柔和绘制光影。
- 主体必须直接对应线索，不额外补充可能误导推理的证物。
- 无标题、说明文字、水印、Logo 或线索卡边框。
- 人物线索引用对应角色图，锁定发型、服装、眼睛和辨识特征。
- 物证线索以物品或环境为主体，不强行加入人物。
- 手机时间等必须精确的信息若生成结果不可靠，使用可控的本地绘制修正，不接受乱码。

地图处理优先级：

1. 使用项目已有地图。
2. 提取 DOCX `word/media` 中的原图。
3. 只有没有原图时才根据剧本重绘；重绘前确认地点与结构。

最终源图保存为无损 PNG。统一 16:9 时优先轻微中心裁切或补边，避免重采样；不得转成 JPEG。记录每张源图的像素尺寸和 SHA-256。

## 5. 嵌入智能对象

每个线索组加入且仅加入一个配图智能对象。`ag-psd` 数据结构：

```js
layer.placedLayer = {
  id: linkedId,
  placed: placedId,
  type: "raster",
  transform: [x1, y1, x2, y2, x3, y3, x4, y4],
  width: sourceWidth,
  height: sourceHeight,
  resolution: { value: 72, units: "Density" }
};

psd.linkedFiles.push({
  id: linkedId,
  name: "01_线索配图.png",
  data: new Uint8Array(fs.readFileSync(sourcePng))
});
```

智能对象图层还需要一份卡面缩放后的 `imageData` 作为 PSD 预览；这份预览不替代 `linkedFiles.data`。保持原始 PNG 字节不变，并只用 `placedLayer.transform` 控制卡面上的大小和位置。

图文布局由模板可用区域决定。优先保证：

- 16:9 图片不拉伸。
- 正文完整可读且不与图片重叠。
- 标题、图片、正文视觉顺序一致。
- 长线索可缩小正文字号，但不得删减内容。

## 6. 更新合成预览

`ag-psd` 不会自动重绘文字、智能对象或顶层合成图。写出前需要：

- 更新文字图层的 `imageData`。
- 为智能对象生成卡面尺寸的预览 `imageData`。
- 将当前可见组重新合成为 `psd.imageData`，避免系统缩略图仍显示旧内容。

## 7. 机械验收

重新读取落盘 PSD，检查：

- 线索清单数 = 顶层组数 = 智能对象数 = `linkedFiles` 数。
- 每组恰有一个竖排标题、一个横排正文和一个智能对象。
- 标题、正文与线索清单逐项一致。
- 所有 `layer.id` 唯一，所有 `placedLayer.id` 能找到对应 `linkedFiles.id`。
- 每个智能对象的 `width`、`height` 等于源 PNG 尺寸。
- 嵌入数据 SHA-256 与源 PNG SHA-256 完全一致。
- 字体名仍为模板字体；顶层 `engineData` 已因刷新策略移除。
- PSD 尺寸、RGB/8 位、文件存在性和可重新解析均正常。

可运行：

```bash
node scripts/validate_clue_psd.js final.psd assets-directory
```

## 8. 视觉验收与交付

逐组渲染预览并制作联系表，人工检查：

- 人物是否对应正确角色。
- 线索视觉重点是否准确。
- 图片是否拉伸、裁切主体或串组。
- 标题是否仍为竖排，正文是否完整、无溢出。
- 地图结构和文字是否保持原样。

只在机械与视觉验收都通过后称为完成。交付最终 PSD、无损 PNG 目录、线索/提示词清单；源剧本、模板和参考图保持不变。
