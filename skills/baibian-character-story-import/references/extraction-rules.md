# 文档提取规则

## 分段顺序

1. 先扫描全文标题和目录，列出所有幕次、角色名和明确公共剧情标识。
2. 用人物介绍或角色总表作为角色名基准，再用故事标题校验。不自行把剧情中的人名当作角色显示名。
3. 每个故事从角色标题之后开始，到下一个同级角色标题、下一幕或下一个功能章节之前结束。角色标题本身不写入正文，除非它明显是故事叙事的一部分。
4. 若幕次标题带副标题，保留原文和原有标点，只清理多余空白。
5. “公共剧情”“公共故事”“小剧场（公共剧情）”等明确公共段生成一条记录并关联全部具体角色。仅出现多个人名不足以判定为公共剧情。
6. “【你的任务】”“任务”等明确任务段需要单独生成记录时，标题沿用相应幕次并追加或保留“任务”，分类默认“目的”；其余人物剧情分类默认“人设”。
7. 用户给出的幕次顺序优先于文档目录顺序。输出时按角色分组，同一角色内部按该顺序排列；每个角色的优先级独立从高到低，不跨角色续排。
8. 用户指定文件夹输入时，可将多个源文档中的记录合并到同一个数据包；用户明确指定的统一分类、优先级或其他字段覆盖自动规则，并应写入每条记录而不是只依赖 `defaults`。
9. 同批 JSON、Markdown 校对目录和合并校对 DOCX 必须来自同一个内存中的记录列表，禁止分别重新扫描或重新排序源文件。这样三份产物的记录数、角色、标题和顺序天然一致。

## 格式转换

以 Word run 为最小单位读取字符、加粗和字体颜色。颜色转为十进制 RGB；主题色无法稳定解析时，在生成说明标注而不猜测。段落中的手动换行写成 `<br>`，文档段落边界写成新的 `<div>`。

不保留样式名、字体、字号、字距、段前段后、行距、首行缩进、对齐、页眉页脚、文本框定位、高亮和底色。对张数异常、文本框与正文顺序不明的文档，先生成预处理报告，不强行生成可导入包。

## DOC 与 WPS

`.doc` 需先用 LibreOffice/WPS 另存为工作副本 `.docx`，不覆盖源文档。转换后对比总页数、角色标题数和开头/结尾段，确认没有丢页或乱序。
